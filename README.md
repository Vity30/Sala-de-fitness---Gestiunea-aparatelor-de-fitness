# Sala de fitness: gestiunea aparatelor

A web app for managing the equipment of a gym. Every machine belongs to a muscle group and is either
working or broken; machines can be added, marked as working or broken and deleted, and each one has
its own page with exercise details: what it does, the muscles worked, how to do it and a recommended
program per level.

**Stack:** React 19 + Vite, React Router 7, json-server 0.17 (mock API).

## Data model

One record per machine (`aparat`), stored in `frontend/db.json` under the `aparate` key.

| Field | Type | Notes |
| --- | --- | --- |
| `id` | number | generated by the server |
| `nume` | text | required, max 100 characters |
| `grupa` | fixed values | `Legs`, `Push`, `Pull`, `Arms`, `Cardio`, `Core`; shown in the app as Picioare, Piept, Spate, Brate, Cardio, Abdomen |
| `functional` | boolean | toggled from the list; a machine added from the form starts as `false` (broken until checked) |
| `img` | text, optional | photo in `frontend/public/img/`; without it the card shows the group's emoji |
| `tip` | fixed values, optional | `Compus`, `Izolare`, `Cardio` |
| `nivel` | fixed values, optional | `Incepator`, `Intermediar`, `Avansat` |
| `descriere` | text, optional | what the exercise does |
| `muschiPrincipali`, `muschiSecundari` | list of text, optional | main and secondary muscles worked |
| `pasi` | list of text, optional | step-by-step execution |
| `respiratie` | text, optional | how to breathe |
| `greseli` | list of text, optional | common mistakes |
| `sfat` | text, optional | coach tip |
| `program` | list, optional | one row per level: `nivel`, `volum` (sets x reps, or duration), `intensitate` (weight as % of 1RM, or speed), `pauza` |

`Core` is the usual English name for the trunk muscles (abs, obliques and lower back), so it is the value
kept in the data; the app shows it as "Abdomen". The values stay in English because they are used in the code
(CSS classes, filters), while the labels are in Romanian.

| --- | --- | --- |
| Zona din sala | relation | Greutati libere, Cabluri, Cardio |
| Responsabil tehnic | relation | the user responsible for the machine (from week 11) |

## Project structure

```
mockup/              Stages 1-2: static HTML/CSS mockup and plain JavaScript data logic
frontend/            Stage 3 on: the React app (Vite)
  db.json            data served by json-server
  public/img/        machine photos
  src/
    pages/           one component per page (list, detail, about, not found)
    components/      Layout, AparatList, AparatCard, AparatForm
    api.js           every HTTP request
    constants.js     muscle groups (value, label, emoji)
    index.css        theme variables and shared classes
ai-log/              AI log for each stage
tw.json              resource description used by the automatic checks
```

## How to run

**Mockup (stages 1-2):** open `mockup/index.html` in a browser; the Stage 2 results are printed in the console (F12).

**App (stage 3 on):**

```bash
cd frontend
npm install
npm run api   # terminal 1: json-server on http://localhost:3001
npm run dev   # terminal 2: the app on http://localhost:5173
```

The API address is read from `VITE_API_URL`; to change it, copy `frontend/.env.example` to `frontend/.env`.

## Stage 5: local state and events

The list moves into React state (`useState`). A checkbox on each card toggles the machine between working and
broken, and a button deletes it; both update the state without changing the old array (`map` and `filter`
create new ones). The header counter is computed on every render, not stored. A button in the header switches
between the light and dark theme by setting `data-theme` on the `<html>` element.

## Stage 7: form and validation

New machines are added from a form on the page: a name (required, at most 100 characters) and a muscle group.
The form is controlled, shows its error next to the fields and sends nothing while the data is invalid. Adding,
toggling and deleting are saved by the API first and only then shown in the list, so they survive a refresh;
while saving, the button is disabled. A new machine starts as broken until it is checked. `tw.json` and the
`data-testid` attributes describe the app for the automatic checks.

## Stage 8: routing and detail page

The app is split into pages with React Router:

| Address | Page |
| --- | --- |
| `/` | the list: equipment status, add form, cards |
| `/aparate/:id` | detail page of one machine |
| `/despre` | about the app |
| anything else | "page not found" |

The header (title, navigation, theme button) is shared by all pages through a `Layout` component, and
`NavLink` marks the current page. Each card's name and photo link to its detail page; an unknown id shows an
error with a way back.

The detail page shows what only fits there: what the exercise does, the main and secondary muscles, the steps,
breathing, common mistakes, a coach tip and a recommended program per level (sets x reps, weight as % of 1RM,
rest; duration and speed for the treadmill). These fields were added to `db.json` for all eight machines.

The styles moved to CSS Modules: every component has its own `.module.css`, and `index.css` keeps only the
theme variables and the shared classes. Both themes are sets of CSS variables: dark (black, yellow and amber)
and light ("sand and amber", a softer daytime version of the dark theme). Switching themes fades smoothly in
Chrome and Edge.
